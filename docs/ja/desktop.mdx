---
title: デスクトップ
description: アクセシビリティツリーを通じて、macOS のネイティブデスクトップアプリをテストします。
---

`@e2e-dev/desktop` はネイティブデスクトップアプリでテストを実行します。テストプロセス内で動くネイティブドライバーを使い、OS のアクセシビリティツリーを通じてアプリを読み取り、操作します。テストでは、ブラウザテストと同じ `agent`、`screen`、`expect` API を使います。

<Note>
  デスクトップエンジンはプロトタイプで、macOS 13 以降でのみ動作します。デスクトップターゲットを含む設定は Windows と Linux でも読み込めます。`--target` で他のターゲットを選べば、それらはそこで実行できます。デスクトップターゲットを含む実行は、テストが始まる前に `UNSUPPORTED_CAPABILITY` で停止します。
</Note>

## セットアップ

ランナーとエンジンをインストールします。

<CodeGroup>
```bash npm
npm install --save-dev e2e @e2e-dev/desktop
```

```bash pnpm
pnpm add --save-dev e2e @e2e-dev/desktop
```

```bash bun
bun add --dev e2e @e2e-dev/desktop
```
</CodeGroup>

macOS では、e2e を起動するアプリに **システム設定 > プライバシーとセキュリティ** で 2 つの権限が必要です。そのアプリとは、ターミナル、IDE、または CI エージェントです。

- **アクセシビリティ**：アプリの読み取りと操作に使います。
- **画面収録**：スクリーンショットに使います。

npm はエンジンと一緒に、お使いの Mac 用のドライバーを `@e2e-dev/desktop-darwin-arm64` または `@e2e-dev/desktop-darwin-x64` としてインストールします。Rust や Xcode は必要ありません。

セットアップを確認します。

<CodeGroup>
```bash npm
npx e2e doctor
```

```bash pnpm
pnpm exec e2e doctor
```

```bash bun
bunx e2e doctor
```
</CodeGroup>

ドライバー、両方の権限、`appPath` のビルドを確認します。

## アプリを指定する

ターゲットの `app.appPath` にビルド済みの `.app` バンドルを設定します。または、`app.bundleId` に `com.apple.calculator` など、インストール済みアプリのバンドル ID や名前を設定します。両方を設定した場合は `appPath` のビルドを起動し、そのバンドル ID は `bundleId` と一致する必要があります。`app.launchArguments` は起動のたびに渡されます。オブジェクトのエントリーは iOS と同じく `-name value` になるため、`{ AppleLanguages: ['fr'] }` を指定するとアプリはフランス語で開きます。

起動したアプリが受け取る環境変数は最小限です（`HOME`、`USER`、`LOGNAME`、`SHELL`、`PATH`、`TMPDIR`、`LANG`、`LC_*`、`__CF_USER_TEXT_ENCODING` と、プロセス追跡用の `E2E_DESKTOP_LAUNCH`）。そのため、シークレット、モデルのキー、CI トークンがアプリに漏れることはありません。macOS は、macOS 自身のアプリ、Apple の App Store アプリ（Numbers、Pages、Xcode）、`restrict` フラグ付きで署名したビルドではこの変数を隠します。そのため、これらのアプリには最後の起動引数として `-E2EDesktopLaunch=<token>` も渡されます。エンジンは App Store アプリを署名で見分けるため、Mac App Store のアプリはすべてこの引数を受け取ります。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { desktop } from '@e2e-dev/desktop';

export default {
  targets: [
    {
      name: 'mac',
      engine: desktop(),
      app: { appPath: 'build/MyApp.app' },
    },
  ],
  credentials: {
    ada: { username: 'ada', password: process.env.ADA_PASSWORD ?? '' },
  },
} satisfies E2EConfig;
```

## テストを書く

`@e2e-dev/desktop` から `test` をインポートします。デフォルトでは、`app.open()` はアプリをバックグラウンドに置いたままにします。前面に出ないとウィンドウを表示しないアプリには、`--headed` を付けて実行します。`desktop({ physicalInput: true })` もアプリを前面に出し、さらに後述の物理入力を有効にします。以前にエンジンが起動したコピーがあれば、先にそのコピーを終了します。自分で開いたコピーには触れず、エンジンが読み取ることも操作することもありません。一度に 1 つのコピーしか動かないアプリは、すでに実行中のコピーに起動を引き渡すため、`app.open()` は失敗し、そのコピーを示します。先にそのコピーを終了してください。どのテストもアプリを終了した状態で終わり、アプリが前回の終了時に保存したウィンドウは復元されません。

```ts title="tests/sign-in.e2e.ts"
import { test } from '@e2e-dev/desktop';
import { credentials, expect } from 'e2e';

test('signs in', async ({ app, screen }) => {
  const ada = credentials.user('ada');
  await app.open();
  await screen.getByRole('textbox', 'Username').fill(ada.username);
  await screen.getByRole('textbox', 'Password').fill(ada.password);
  await screen.getByRole('combobox', 'Plan').selectOption('Team');
  await screen.getByRole('button', 'Sign in').tap();
  await expect(screen.getByTestId('status')).toContainText('Signed in as ada');
});
```

ロールには Web と同じ名前を使います：`textbox`、`checkbox`、`combobox`、`button`。ツリーは静的テキストを `text` として列挙しますが、これは `getByRole` のロールではありません。`getByText` で探します。コントロールの名前は、macOS のアクセシビリティが与える名前、つまりタイトルまたはアクセシビリティラベルです。ボタンのタイトルはその名前でありテキストでもあるため、`getByText('Sign in')` は同じ文字列の静的テキストに加えてボタンも見つけます。`getByRole('button', 'Sign in')` はボタンだけを見つけます。`getByPlaceholder` は未対応です。エンジンはラベルのないフィールドにプレースホルダーで名前を付けるため、そのフィールドは `getByRole('textbox', 'Username')` で探します。`getByTestId` はコントロールの `AXIdentifier`（AppKit の `accessibilityIdentifier`、SwiftUI の `.accessibilityIdentifier`）を探します。

## desktop フィクスチャ

| メソッド | 動作 |
| --- | --- |
| `windows()` | アプリの開いているウィンドウ |
| `waitForWindow(trigger, { timeout }?)` | `trigger` を実行し、それが開くウィンドウを待って、そのウィンドウをアクティブにします |
| `window({ title }, { timeout }?)` | タイトルでウィンドウを待って返します。アクティブにはしません |
| `keyboard.press(key)` | キーまたは `ControlOrMeta+2` のような組み合わせを、アクティブウィンドウに送ります。キーボードフォーカスを受け取るコントロールがないアプリ向けです |
| `keyboard.type(text)` | フォーカス中のフィールドにテキストを入力します |
| `closeApp()` | アプリを終了します。`app.open()` で再び起動します |
| `platform` | アプリが動作する OS で、`'macos'` です |

## 複数のウィンドウを扱う

`screen` はアクティブウィンドウを読み取ります。テストがウィンドウを選ぶまでは、アプリのフォーカス中のウィンドウがアクティブウィンドウです。そのため、フォーカスを取るダイアログは、専用のステップなしで読み取れます。`desktop.waitForWindow()` は、ウィンドウを開くステップを実行し、そのウィンドウをアクティブにします。そのウィンドウは、どのウィンドウにフォーカスがあっても、閉じるまでアクティブのままです。閉じたあとは、`screen` は再びフォーカス中のウィンドウを読み取ります。

```ts
const settings = await desktop.waitForWindow(() =>
  screen.getByRole('button', 'Settings…').tap(),
);
await expect(screen.getByRole('checkbox', 'Launch at login')).toBeVisible();

const main = await desktop.window({ title: 'My App' });
await main.activate();
await settings.close();
```

ウィンドウには `title()`、`isActive()`、`isClosed()`、`activate()`、`close()` があります。どれも macOS に問い合わせるため、すべて `await` してください。`close()` はウィンドウの閉じるボタンを押すため、未保存の変更について確認するために開いたままになるウィンドウでは失敗します。`title` には完全一致の文字列または `RegExp` を指定します。アプリが自分で開くウィンドウには `desktop.window()` を使います。

## Web との違い

| 項目 | デスクトップターゲットの動作 |
| --- | --- |
| 入力 | アプリはバックグラウンドで動作します。アクションは macOS Accessibility API を使い、キーはアプリ自身のイベントキューに入るため、マウスとキーボードは自由に使えます。バックグラウンドでウィンドウを開かないアプリ（書類ベースのアプリなど）には `--headed` または `physicalInput: true` が必要です。無効なコントロールへのタップ、`doubleTap`、`secondaryTap`、`check`、`uncheck`、`fill`、`clear`、`selectOption` は、アクションのタイムアウト内でアプリがコントロールを有効にするのを待ち、その後 `ACTION_FAILED` で失敗します（拒否されるため、何も送信されていません）。`check` や `uncheck` が求める状態をすでに示しているチェックボックスには何もしません。 |
| 物理入力 | `doubleTap`、`hover`、座標指定のタップには `desktop({ physicalInput: true })` が必要です。これはアプリを前面に出し、実際のポインターを使います。このとき、キーと文字入力は実際のキーボードを使います。クリックは、ポインターの移動前または移動後に、ポインターの下に別のウィンドウ（そのアプリのものでも他のアプリのものでも）や、要素の内側のコントロール（行のボタンやテキストフィールド）がある場合に拒否されます。座標へのタップやホバーは、その位置で別のウィンドウが上にある場合に拒否されます。ダブルクリックは、人が行う場合と同じく 1 つのジェスチャーです。最初のクリックが送られると、それが何を開いたとしても、すぐに 2 回目が続きます。フローティングウィンドウが対象領域に重ならないよう注意してください。 |
| キー | `press` と文字入力は、アプリのキーウィンドウでフォーカス中のコントロールにのみキーを送ります。`physicalInput` なしでは、`activate()` でアクティブにしたウィンドウがキーウィンドウでない場合、そのウィンドウにキーは届きません。名前付きキー、英字、数字、``, . / ; ' [ ] \ - = ` `` に対応し（`!` や `é` など他の文字は拒否します）、`ControlOrMeta+q` などのシステムショートカットはブロックします（代わりに `desktop.closeApp()` を使います）。ショートカットの文字は Mac のキーボードレイアウト上の文字なので、`ControlOrMeta+a` は AZERTY でも「すべてを選択」です。数字や記号を含むショートカットには、その文字を Shift なしで入力できるレイアウトが必要です。AZERTY では、`ControlOrMeta+2` は未対応として失敗します。`physicalInput` なしでは、`ControlOrMeta` のショートカットはアプリのメニューバーにしか届きません。メニュー項目のショートカットは動作しますが、フォーカス中のコントロールやキーウィンドウが処理するショートカット（コピー、ペースト、すべてを選択、SwiftUI ボタンの `.keyboardShortcut`）は何も起こさず、それでも `press` は成功します。これらには `physicalInput: true` を使います。ロケーターの `press` には、キーボードフォーカスを受け取るコントロールが必要です。そのようなコントロールがないアプリ（Calculator など）には、`desktop.keyboard.press()` を使います。 |
| 選択 | `selectOption` はインデックスではなく選択肢のラベルで照合します。テーブルの行のラベルは、アクセシブルネームと同じく、行が表示するすべてのテキストをセルごとに並べたものです。2 つの行が表示するラベルは拒否されます。ポップアップボタンでは、選んだ選択肢をボタンが表示していることを確認します。無効な選択肢は、アクションのタイムアウト内でアプリが有効にするのを待ち、その後、その選択肢を示す `ACTION_FAILED` で失敗し、メニューは閉じます。同じタイトルの選択肢が 2 つある場合はメニューから有効な方を選び、すでにそのタイトルを表示しているポップアップはそのままにします。閉じたポップアップは、2 つを見分けるための項目を表示しないためです。編集可能なコンボボックスには、代わりに `fill()` を使います。入力した値を受け付けないコンボボックスは拒否されるため、コンボボックスをタップしてから選択肢をタップします。 |
| ウィンドウ | `screen` は[アクティブウィンドウ](#work-with-several-windows)を読み取ります。テストがアクティブにしたウィンドウ、なければフォーカス中のウィンドウ、なければアプリのメインウィンドウ、なければ最初の可視ウィンドウです。macOS 27 がアプリの上に表示することがある Siri のダイアログは、テストがアクティブにした場合にのみ読み取ります。シートが開いているウィンドウは、フォーカス中として扱います。シートと、開いているコンテキストメニューやポップアップメニューは含まれるため、`getByRole('menuitem', 'Copy')` はメニューの項目を見つけます。ウィンドウ枠の操作部（閉じる/最小化/拡大）は含まれません。最小化したウィンドウと、リストの表示範囲外にスクロールされた行は非表示として読み取るため、`getByRole` はそれらをスキップします。`getByText` と `getByTestId` は非表示のノードにも一致します。どちらもテキストまたは識別子を持つノードを見つけるため、`getByText('Item 40')` は行ではなく行のラベルを見つけます。非表示のノードへのタップ、セカンダリタップ、`check`、`uncheck` は、先にそのノードを表示範囲までスクロールするか、拒否されます。このスクロール後の失敗は、リストが動いているため、効果があった可能性のあるアクションとして `ACTION_FAILED` で失敗し、リトライされることはありません。別の macOS Space にあるウィンドウも読み取れます。 |
| 読み取り | 開いているウィンドウがないアプリだけが空として読み取られます。画面がロックされている場合、ウィンドウツリーが `maxDepth` より深い場合、またはウィンドウが 1 回の読み取りで扱える 8,000 要素を超える要素を持つ場合、ロケーターは誤って「見つからない」と返さず、タイムアウトまでリトライを続け、そのウィンドウのスクリーンショットは拒否されます。ロックされた画面では `app.open()` が失敗します。 |
| メニューバー | アプリのメニューバーはまだ読み取れません。メニュー項目はキーショートカット（`press`）で実行します。 |
| Web コンテンツ | ブラウザウィンドウ、Electron アプリ、Web ビューは未対応です。Web アプリには `@e2e-dev/web` を、Electron アプリには [`@e2e-dev/electron`](/electron) を使います。 |
| ワーカー | デスクトップターゲットごとに 1 ワーカーに制限されます。`physicalInput: true` のデスクトップターゲットを 2 つ実行する場合は、カーソルとキーボードを奪い合わないよう `workers: 1` を設定します。 |
| スクロール | `scrollTo(edge)` は未対応で、`UNSUPPORTED_CAPABILITY` で失敗します。代わりに `scrollUntilVisible` を使います。 |
| 状態 | `app.clearState()` と `app.back()` はまだ未対応です。エンジンは状態を保存せず、動画も録画しないため、`test.setup` セッションと `video: 'on'` はテストの収集時に拒否されます。 |
| 未対応 | `getByPlaceholder`、`toBeInViewport`、`toBeEmpty`、`blur`、`longPress`、`dragTo`、`setInputFiles`、タップの `modifiers`、`selectOption({ index })` は、未対応であることを伝えるメッセージで失敗します。 |
| シークレット | パスワードフィールドは値を公開せず、スクリーンショットでは黒く塗りつぶされます。スクリーンショットがパスワードフィールドを覆えない場合や、ウィンドウが `maxDepth` より深いか 1 回の読み取りで扱える大きさを超える場合は、保存せずに失敗します。 |

一時的な状態は実行の終了時にクリーンアップされます。実行の途中でアプリやワーカーが強制終了された場合は、次のデスクトップ実行が残ったアプリプロセスを自動的にクリーンアップします。

<Accordion title="デスクトップのその他のエッジケース">
- **読み取れないウィンドウ：** 読み取れないウィンドウが空として読み取られることはないため、そのウィンドウで `not.toBeVisible()` は成功しません。
- **ポップアップメニュー：** ポップアップボタンで存在しない選択肢を選ぶと、メニューは再び閉じます。メニューが開いたままの場合は、エラーがそのことを伝えます。
</Accordion>

## オプション

| オプション | 型 | デフォルト |
| --- | --- | --- |
| `snapshot` | `'full' \| 'interactive'` | `'full'` |
| `physicalInput` | `boolean` | `false` |
| `settle` | `number \| false` | `150` |
| `maxDepth` | `number` | `24` |

`snapshot: 'interactive'` では、エージェントの観察は静的テキストを除いたコントロールだけを読み取ります。どちらの場合も、ロケーターと `expect` はウィンドウ全体を読み取ります。`physicalInput` は実際のポインターとキーボードの使用を許可します。これらはカーソルを動かし、アプリを前面に出します。`settle` は、エージェントのアクションのあと、エージェントが画面を読み取るまでエンジンが待つ時間で、単位はミリ秒です。`maxDepth` は、読み取りがウィンドウを何階層までたどるかで、1 から 50 を指定します。深くネストしたアプリで、読み取りが一部だけになりロケーターがタイムアウトする場合は、値を上げてください。
