Um teste combina três tipos de passo:

| Passo | API | Chama um modelo? |
| --- | --- | --- |
| [Objetivo](#goals) | `agent.act` | Sim, a menos que seja reproduzido do [cache](/cache) |
| [Asserção](#assertions) | `agent.assert`, `agent.waitFor`, `agent.extract` | Sim |
| [Localizador](#locators) | `screen` e `expect` | Não |

Se você usa um [executor personalizado](/executors), `act` e `assert` também
não precisam de um LLM.

```ts title="tests/todos.e2e.ts"
import { describe, test, expect } from 'e2e';

describe('todos', () => {
  test('the Done filter shows only completed todos', async ({ app, agent, screen }) => {
    await app.open('/todos');
    await agent.act('add todos "Buy milk" and "Walk the dog"');
    await agent.act('complete "Buy milk"');
    await agent.waitFor('"Buy milk" is completed and "Walk the dog" is open');

    await screen.getByRole('tab', 'Done').tap();

    await expect(screen.getByTestId('todo')).toHaveCount(1);
    await agent.assert('the only todo listed is "Buy milk"');
  });
});
```

Cada teste verifica um comportamento com um objetivo: prepare o estado
inicial, aja rumo a esse objetivo e depois faça asserções sobre o resultado.

Dê nome com `const` a localizadores e valores repetidos, compartilhe a
preparação com um hook ou uma fixture e use uma pequena função auxiliar ou um
[page object](/page-object-model) quando vários testes controlarem a mesma
tela, mantendo as verificações de resultado visíveis no teste. Deixe instruções
curtas e de uso único direto no teste (ou dê nome às longas com uma `const`
local) e compartilhe instruções recorrentes em um módulo TypeScript, com
`params` para os dados de teste.

Sempre use `await` em toda chamada de `agent`, `screen` e `expect.poll`. Se um
teste terminar com um passo ainda em andamento, o e2e faz o teste falhar.

## Objetivos

`agent.act` recebe uma instrução em linguagem natural, faz as interações
necessárias para alcançar o objetivo e lança um erro se não conseguir. Use os
nomes de campos e botões mostrados na tela e indique a ordem quando ela
importar (por exemplo, preencher os dados de envio, escolher uma opção de
entrega e fazer o pedido).

Comece com uma chamada para o comportamento em teste. Divida a chamada no ponto
de uma transição significativa quando o próximo passo precisar de um estado
conhecido (como a página de pagamento de uma finalização de compra longa),
quando um fluxo longo arriscar estourar os orçamentos `maxSteps` ou
`maxModelCalls`, ou quando uma falha no meio precisar de uma fronteira de passo
própria. Explique por que a divisão é necessária e espere pelo estado de tela
intermediário antes de continuar. Cada chamada tem seus próprios
[orçamentos](/reference/agent#budgets) e pode ser reproduzida a partir da sua
própria gravação.

```ts title="Complete one checkout across two screens"
test('places an order with a saved card', async ({ app, agent, screen }) => {
  await app.open('/checkout');

  // The saved card can load after the Payment heading appears.
  await agent.act('Fill the Shipping address with {address}, then choose Continue to payment.', {
    params: { address: '12 Market Street' },
  });
  await screen.getByRole('radio', 'Test card').waitFor();
  await agent.act('Select the saved Test card and choose Place order.');

  await expect(screen.getByText('Order confirmed')).toBeVisible();
});
```

- **Espere depois da preparação e faça as asserções no fim.** Quando a
  preparação usa `agent.act`, termine a preparação com uma espera pelo estado
  inicial e verifique o resultado final no bloco de asserções. Qualquer espera
  ou verificação posterior que passe confirma os objetivos anteriores para o
  [cache de replay](/cache#when-a-recording-is-written).
- **Siga o texto da UI.** Use os rótulos e os termos que de fato aparecem na
  tela.
- **Passe os dados em `params`.** Para senhas ou tokens, passe uma referência
  `Secret` para que o modelo nunca veja o valor em texto puro. Veja
  [Autenticação](/authentication).
- **Envolva valores dinâmicos em `unique()`.** Timestamps ou e-mails novos
  mudam a cada execução; envolvê-los permite que o
  [cache ainda reproduza o passo](/cache#what-must-match):

```ts
import { unique } from 'e2e';

const email = `ada+${Date.now()}@example.test`;
await agent.act('sign up with email {email}', { params: { email: unique(email) } });
```

`agent.act` obtém capturas de tela automaticamente quando a árvore de texto não
basta e, nas engines compatíveis, pode tocar ou digitar por coordenadas. Se um
objetivo falhar, torne a instrução mais precisa ou mova a terminologia
compartilhada do domínio para o [`context`](/agents) do agente.

## Asserções

As asserções do agente inspecionam a tela atual de forma independente. O
modelo vê a sua afirmação, um snapshot da tela com dados sensíveis ocultados, a
URL ou localização atual e o `context` do agente, não os passos anteriores nem
os resumos de `agent.act`.

- **`agent.assert`** verifica a tela neste momento e falha se a afirmação for
  falsa ou se não houver evidências suficientes.
- **`agent.waitFor`** espera até que uma condição se torne verdadeira e chama
  o modelo somente quando a tela ou a localização muda.
- **`agent.extract`** extrai dados estruturados da tela para qualquer tipo
  [Standard Schema](https://standardschema.dev), como Zod.

```ts
import { expect } from 'e2e';
import { z } from 'zod';

await agent.assert('the dashboard shows a trial badge');
await agent.waitFor('a download link appears', { timeout: 120_000 });
await agent.assert('the chart trends upward', { vision: true });

const data = await agent.extract('every todo title', {
  schema: z.object({ titles: z.array(z.string()) }),
});
expect(data.titles).toContain('Buy milk');
```

Ao verificar um texto gerado pelo modelo, faça a asserção sobre o significado,
não sobre as palavras exatas. Quando as palavras exatas importam, use um
[localizador](#locators).

Para verificações visuais, como gráficos ou alinhamento de layout, passe
`vision: true` (ou `vision: 'only'` para avaliar só a captura de tela). Lembre-se
de que imagens acrescentam tokens de entrada. Veja as
[opções de visão](/reference/agent#vision).

## Localizadores

Localizadores apontam diretamente para controles conhecidos, sem chamada ao
modelo. Use-os sempre que você souber a interação exata ou o valor exato que
quer verificar.

```ts
// Role and name first, label second, test ID last.
await screen.getByRole('button', 'Sign in').tap();
await screen.getByLabel('Email').fill('ada@example.test');

// Scope into a row.
const row = screen.getByRole('listitem').filter({ hasText: 'Design review' });
await row.getByRole('button', 'Archive').tap();

// Gestures and coordinates.
await screen.swipe({ direction: 'up' });
await screen.getByRole('image', 'Seat map').tap({ position: { x: 120, y: 48 } });

// Assertions retry until they pass or time out.
await expect(screen.getByRole('status')).toHaveText('2 remaining');
```

- Ações e asserções de elemento único falham se um localizador corresponder a
  mais de um controle. Restrinja-o com `.filter()`, `.first()` ou `.nth()`.
- Leituras diretas como `textContent()` esperam que o elemento apareça e depois
  o leem uma vez, sem tentar novamente em busca de um valor específico.

Veja a [referência de screen](/reference/screen) e a
[referência de expect](/reference/expect#locator-matchers). Para rotas,
cookies, diálogos e downloads, veja
[Trabalhando com o navegador](/browser).

## Organize os testes

```ts
import { beforeEach, describe, test } from 'e2e';

describe('billing', { tags: ['billing'] }, () => {
  beforeEach(async ({ app }) => { await app.open('/billing'); });

  test('upgrades', { retries: 2, timeout: 60_000 }, async ({ agent }) => {
    await agent.act('upgrade to Pro');
  });
});

test('needs two organizations', async ({ app }) => {
  test.skip((await countOrganizations()) < 2, 'nothing to switch to');
  await app.open('/organizations');
});
```

- **Comece perto da tela que você está testando.** Cada teste roda na sua
  própria tentativa, então pule a navegação repetitiva criando dados em
  fixtures, restaurando uma [sessão salva](/authentication), abrindo uma URL
  direta ou usando um [deep link](/mobile#the-device-fixture) no mobile. (Os
  navegadores começam com um contexto novo a cada tentativa; os dispositivos
  mobile mantêm o estado do app até você chamar `app.open()` ou
  `app.clearState()`.)
- **Pule condicionalmente** com `test.skip(condition, reason)`.
- **Encadeie testes dependentes** com `{ serial: true }` em um bloco
  `describe`, para que rodem em ordem em um único worker e façam novas
  tentativas juntos.
- **Compartilhe preparação e limpeza** com `test.extend`. Veja
  [Escrevendo fixtures](/fixtures).
- **Tenha fixtures de plataforma tipadas** importando `test` de
  `@e2e-dev/web`, `@e2e-dev/mobile` ou `@e2e-dev/desktop` para `browser`,
  `device` ou `desktop`.

A [referência de test](/reference/test) mostra todas as opções.

## Rode um teste

<CodeGroup>
```bash npm
npx e2e run tests/signup.e2e.ts:12   # the test at line 12
npx e2e run --grep checkout          # tests with a matching title
npx e2e run --target web             # one target
```

```bash pnpm
pnpm exec e2e run tests/signup.e2e.ts:12   # the test at line 12
pnpm exec e2e run --grep checkout          # tests with a matching title
pnpm exec e2e run --target web             # one target
```

```bash bun
bunx e2e run tests/signup.e2e.ts:12   # the test at line 12
bunx e2e run --grep checkout          # tests with a matching title
bunx e2e run --target web             # one target
```
</CodeGroup>

A [referência da CLI](/reference/cli#e2e-run) mostra todas as flags.
