Rode os passos do agente com um plano que você já paga. Faça login uma vez e
depois coloque o modelo do plano em `e2e.config.ts`.

| Plano | Como conectar |
| --- | --- |
| ChatGPT Plus ou Pro | `npx e2e login openai` |
| GitHub Copilot | `npx e2e login github-copilot` |
| OpenCode Console (OpenCode Zen e OpenCode Go) | `npx e2e login opencode-console` |
| SuperGrok ou X Premium+ | `npx e2e login spacexsi` |
| Claude Max ou Team (Claude Code) | Chave de API, paga com os créditos mensais de API do plano, não com os limites de uso dele |
| Login do Claude Code ou do Codex | [Rode os passos no seu agente de código](#use-your-coding-agent) |

## Configure

Em um projeto novo, rode `e2e init` e selecione seu plano
([Início rápido](/quickstart)). Em um projeto existente, instale os pacotes,
faça login e defina `agents: { default: agent }` em `e2e.config.ts`.

<Tabs>

<CodeGroup>
```bash npm
npm install -D ai @ai-sdk/openai
npx e2e login openai
```

```bash pnpm
pnpm add -D ai @ai-sdk/openai
pnpm exec e2e login openai
```

```bash bun

bunx e2e login openai
```

## Escolha um modelo

`e2e models` lista os ids de modelo que seu login pode usar:

<CodeGroup>
```bash npm
npx e2e models            # every stored login
npx e2e models openai     # one provider
```

```bash pnpm
pnpm exec e2e models            # every stored login
pnpm exec e2e models openai     # one provider
```

```bash bun
bunx e2e models            # every stored login
bunx e2e models openai     # one provider
```
</CodeGroup>

O id nem sempre é o nome que o app do fornecedor mostra.

Com `OPENCODE_API_KEY` definida, `e2e models opencode-console` lista os ids
que essa chave disponibiliza, a mesma chave que `opencodeConsole()` usa no
lugar do login.

- **Copilot** marca os modelos como `not enabled` (ative-os nas
  configurações do GitHub Copilot ou peça ao administrador da sua
  organização) ou `no chat or responses` (escolha outro modelo). O Copilot
  Free só disponibiliza modelos por
  [seleção automática de modelo](https://docs.github.com/en/copilot/get-started/plans),
  então chamar um id de modelo específico costuma falhar; escolha outro id ou
  um [provedor de API](/models).
- **OpenCode Console** lista modelos `go/` somente se você tiver o Go, e
  esconde os modelos desativados e os gratuitos do Zen. Em `providerOptions`,
  use a chave `opencode` para modelos de chat completions e, nos outros
  casos, `openai`, `anthropic` ou `google`.

## Ajuda com o login

- **ChatGPT** abre o seu navegador. Passe `--device` para usar um código de
  dispositivo em vez disso.
- **Copilot** reutiliza o seu login do GitHub CLI (`gh`). Sem o `gh`, passe
  em `--client-id` o id do seu próprio app OAuth do GitHub com o device flow
  ativado (adicione `--enterprise-url` para o GitHub Enterprise).
- **OpenCode Console** exibe um código de dispositivo para você aprovar no
  seu workspace. Para trocar de workspace depois, rode
  `npx e2e logout opencode-console` e faça login de novo.
- **SuperGrok** exibe um código de dispositivo e a URL de verificação.

Rode `npx e2e login` sem argumentos para ver quais contas estão conectadas,
e `npx e2e logout` para remover uma. Tokens expirados são renovados
automaticamente (inclusive entre workers em paralelo). Se um login salvo
deixar de funcionar, o e2e diz qual comando `npx e2e login <provider>` rodar
de novo. Veja a [referência da CLI](/reference/cli#e2e-login) para todas as
flags.

## CI

Use chaves de API na CI. O Claude Max ou Team já usa uma. Para o OpenCode
Console, defina `OPENCODE_API_KEY` com uma chave de API da assinatura do
OpenCode Go ou com uma chave de API de conta de serviço criada no Console
(Service Accounts e depois API Keys). Para ChatGPT, Copilot e SuperGrok, use
um [provedor de API](/models).

[`E2E_OAUTH_CREDENTIALS`](/reference/environment) pode passar um login salvo
para a CI, mas o e2e não salva os tokens renovados de volta nela. Um login com
refresh token rotativo funciona ali só por tempo limitado.

## Use seu agente de código

`@e2e-dev/acp` roda `agent.act` e `agent.assert` no Claude Code ou no Codex
pelo [Agent Client Protocol](https://agentclientprotocol.com). O agente entra
com o próprio login ou a própria chave de API, então o e2e não precisa de um
provedor de modelo.

O agente recebe `complete_step` e as ferramentas de ação do agente embutido
para os verbos que a engine do alvo suporta. O runner grava cada ação, então
os passos são reproduzidos do [cache](/cache) sem o agente. Seus testes não
mudam.

<Tabs>
  <Tab title="Claude Code">
Instale o pacote e o adaptador do Claude Code feito pela Zed. Faça login com
`claude` ou defina `ANTHROPIC_API_KEY`.

<CodeGroup>
```bash npm
npm install -D @e2e-dev/acp @agentclientprotocol/claude-agent-acp
```

```bash pnpm
pnpm add -D @e2e-dev/acp @agentclientprotocol/claude-agent-acp
```

```bash bun
bun add -d @e2e-dev/acp @agentclientprotocol/claude-agent-acp
```
</CodeGroup>

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { claudeCode } from '@e2e-dev/acp';

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
  agents: { default: { executor: claudeCode({ model: 'sonnet' }) } },
} satisfies E2EConfig;
```
  </Tab>
  <Tab title="Codex">
Instale o pacote e o adaptador do Codex e depois faça login com
`codex login`, ou defina `OPENAI_API_KEY` ou `CODEX_API_KEY`. Quando o Codex
não tem login, `codex()` faz o login dele com essa chave, e o Codex salva a
chave como o login dele (em `CODEX_HOME/auth.json` com o armazenamento
padrão) até você rodar `codex logout`. Quando `APP_SERVER_LOGS` está
definida, `codex()` pula o login com chave de API para que o log do
adaptador não escreva credenciais em texto puro (um login salvo continua
funcionando). Passe `env: { OPENAI_API_KEY: '' }` para esconder do
Codex uma chave que o seu app usa, e inicie a primeira sessão em um
`CODEX_HOME` novo sem outras sessões ao mesmo tempo, para que o Codex
inicialize o próprio estado local sem problemas.

<CodeGroup>
```bash npm
npm install -D @e2e-dev/acp @agentclientprotocol/codex-acp
```

```bash pnpm
pnpm add -D @e2e-dev/acp @agentclientprotocol/codex-acp
```

```bash bun
bun add -d @e2e-dev/acp @agentclientprotocol/codex-acp
```
</CodeGroup>

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { codex } from '@e2e-dev/acp';

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
  agents: { default: { executor: codex() } },
} satisfies E2EConfig;
```
  </Tab>
</Tabs>

`claudeCode()` e `codex()` aceitam estas opções:

| Opção | O que faz |
| --- | --- |
| `model` | Qual modelo usar (por exemplo, `'sonnet'`). Sem esta opção, o agente usa o próprio modelo padrão; se o agente não oferecer o modelo pedido, o erro lista os modelos disponíveis. |
| `env` | Variáveis de ambiente extras para o processo do agente. |
| `system` | Instruções extras acrescentadas ao prompt inicial do agente. |
| `name` | Rótulo mostrado para este executor nos relatórios. |

### O que o agente pode usar

Como as ações feitas com as ferramentas próprias de um agente de código
(shell, sistema de arquivos, busca na web) não são gravadas e não podem ser
reproduzidas com segurança, o e2e restringe o agente estritamente às
ferramentas de passo:

- As sessões abrem em um diretório temporário vazio, sem acesso ao sistema
  de arquivos nem ao terminal.
- Só os pedidos de permissão de ferramentas de passo são aprovados; todos os
  outros são rejeitados.
- Se o agente chamar mesmo assim uma das próprias ferramentas, o e2e faz o
  passo falhar na hora e fecha a sessão, para que os passos seguintes
  comecem do zero.

Os dois presets também desativam, nessas sessões, as ferramentas próprias do
agente, os servidores MCP do usuário e o acesso ao shell e à web.

<Accordion title="Detalhes do isolamento por preset">
- **Claude Code:** nenhuma ferramenta embutida, nenhuma configuração de
  usuário, de projeto ou local, nenhum servidor MCP além das ferramentas de
  passo, nenhuma sessão salva e nenhum desvio dos pedidos de permissão.
- **Codex:** modo somente leitura, sem shell, busca na web, apps, plugins,
  navegador, computer use ou snapshots do shell (que copiariam as chaves do
  ambiente para o disco), e todos os servidores MCP do usuário no Codex
  desativados nessas sessões. Se o Codex iniciar um subagente, o e2e faz o
  passo falhar como com qualquer outra ferramenta não autorizada.
</Accordion>

### Segredos

Um parâmetro secreto chega ao agente só pelo nome. Quando a engine do alvo
consegue preencher segredos, o agente chama `type_secret` e o runner digita o
valor, como no agente embutido.

O processo do agente recebe seu ambiente sem as variáveis `E2E_SECRET_*` e
`E2E_USER_*`.

<Warning>
Um segredo em qualquer outra variável chega ao agente. Exemplos são `API_KEY`
por trás de `secrets: { apiKey: process.env.API_KEY }` ou a variável de onde
um valor de `E2E_SECRET_*` foi copiado. Mantenha segredos somente em
`E2E_SECRET_*` e `E2E_USER_*`.
</Warning>

<AccordionGroup>
  <Accordion title="Como um teste roda">
Uma sessão do agente atende uma tentativa de teste. O primeiro passo do
agente que o cache não consegue reproduzir a inicia. Cada passo seguinte é
mais uma mensagem na mesma conversa, e a sessão fecha quando a tentativa
termina, ou antes, em um passo com `POLICY_DENIED`.

Cada mensagem leva o passo, os parâmetros não secretos dele, os passos feitos
até agora e a tela atual. Os resultados das ações dizem o que mudou na tela,
e um `screenshot` chega ao agente como imagem.

Uma asserção não pode mudar a tela. `observe`, `screenshot`, rolar e fazer
hover continuam funcionando. O agente termina todo passo com `complete_step`:
`passed`, `failed` ou `blocked` com um código de erro, como faz o agente
embutido.
  </Accordion>
  <Accordion title="Limites">
  - O Agent Client Protocol não informa as requisições ao modelo. Cada turno
    de prompt conta como uma chamada ao modelo em `maxModelCalls`, com os
    tokens e o custo dele quando o agente os informa. `maxSteps` e o tempo
    limite do passo limitam o turno.
  - `waitFor` e `extract` usam os julgamentos embutidos, então precisam do
    `model` da entrada do agente.
  - Uma entrada de agente com `executor` não aceita `tools`, então o agente
    não recebe ferramentas do projeto de `defineTool`.
  </Accordion>
</AccordionGroup>
