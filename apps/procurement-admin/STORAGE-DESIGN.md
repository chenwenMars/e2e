# 项目目录共享存储方案（已确认）

## 目标

手工浏览器、E2E 新浏览器，以及同一项目的 dev/preview 服务，共享项目目录中的供应商、采购申请、附件、审批历史及每日编码流水。保留当前 IndexedDB 中包括 `202611080007` 在内的数据。

## 方案

推荐复用现有 Vite 进程：开发和预览服务均挂载 `/api/procurement/` 本地接口，由 Node 读写固定路径 `apps/procurement-admin/.data/procurement.sqlite`。不引入独立后端进程、外部数据库或云服务。

SQLite 是项目内的文件。采用 Node 内置 SQLite 能力，不新增数据库依赖；SQLite 事务和唯一索引保护每日流水、版本冲突、审批状态和供应商引用。相比 JSON 整文件覆盖，它能直接处理多个 Vite 服务进程同时写同一份数据，不需要自行实现文件锁。

## 数据与行为

- `src/data.ts` 改为调用同源接口，业务校验复用现有领域规则，并在服务端数据入口执行。浏览器不再维护独立业务副本。
- 申请和供应商保存在 SQLite 中，附件以原始字节及文件元数据保存，保证下载内容一致。
- 采购编码继续使用北京时间 `yyyyMMdd` 加四位每日流水。导入时保留现有编码并将计数器推进到已使用最大值；不能因重启或更换浏览器回到 0001。
- 使用事务执行保存、提交、审批、删除和重置；错误明确返回并显示。存储不可读、损坏或接口失败时直接报错，不退回 IndexedDB 或恢复初始数据。
- 默认数据路径由项目绝对路径定位，不随启动 cwd 或服务端口改变；数据文件及 SQLite 运行文件加入 gitignore，不进入构建静态目录。
- 两个浏览器在进入页面、刷新或完成操作后读取同一份数据；本次不加入实时推送。

## E2E 与数据共享

按本次需求，默认 E2E 和手工页面使用同一数据文件，因此 E2E 创建/修改的数据会出现在手工页面，删除或重置也作用于同一份数据。

- 修改常规用例，使用独立测试记录和唯一标题，避免重复运行定位到多条旧记录；不在测试启动时清空共享数据，不覆盖用户申请。
- 数据存储自身的破坏性回归及迁移测试使用显式临时文件，并验证测试确实不会接触默认共享文件。
- 提供明确的数据目录配置用于需要隔离的回归；默认仍为共享，不能在后台偷偷换成隔离库。
- 首页重置确认文案明确提示会影响所有浏览器。

1. 两个不同浏览器上下文读取同一申请；A 创建，B 刷新可查询；B 修改，A 可读取。

3. 重启服务后记录、附件内容和每日流水保留。
4. 直接读取既有 SQLite 记录，保留原编码、状态、历史及附件；确认无迁移导航、页面或导入接口。
5. 损坏存储和接口错误明确失败，不生成演示成功记录。
6. 构建、类型检查、领域测试、常规 E2E 及共享/隔离存储验证通过；更新 README。
